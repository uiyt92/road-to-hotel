# 5 Points 거시 전략론 HTML 강의 덱 설계

## 1. 목표

기존 30장 PowerPoint 강의안을 외부 강의 현장에서 바로 실행할 수 있는 단일 HTML 발표 자료로 재구성한다. 핵심 목표는 PPT의 내용을 웹페이지에 옮기는 것이 아니라, 발표 화면의 문장 밀도를 낮추고 도표·사례·판단 구조를 더 선명하게 보여주는 것이다.

주요 청중은 여성과 대화 경험은 있지만 2:2 메이드 자리에서 다음 행동이 막히거나, 성적·감정적 대화와 다음 동선으로 자연스럽게 이어가지 못하는 남성이다.

## 2. 선택한 방식

외부 라이브러리가 없는 단일 HTML 슬라이드 덱으로 만든다.

- 인터넷 없이 실행 가능
- 별도 설치나 빌드 과정 없음
- 16:9 전체화면 발표
- 키보드·클릭·터치 이동
- 발표자 노트 패널
- 인쇄 및 PDF 저장 지원
- 기존 PPTX와 PDF는 현장 백업으로 유지

Reveal.js 같은 외부 프레임워크는 기능이 과하고 현장 네트워크·파일 구성 의존성을 만든다. 긴 스크롤 웹페이지는 복습용으로는 좋지만 발표 중 한 장에 집중시키기 어렵다.

## 3. 콘텐츠 구조

기존 30장 순서를 유지한다.

1. 도입과 문제 정의
2. 5 Points 전체 지도
3. 마인드셋
4. 상황 읽기: 권력·텐션·의미·안전
5. 프레임 컨트롤
6. 팀플레이: 리더·밸런서
7. 협상력: 명분·동선·기세·선택권
8. 이태원 사례
9. 워크숍과 롤플레이
10. 정리 및 연구·안전 부록

성공 기준은 다음처럼 표현한다.

- 1차 기준: 여성에게 감정적 반응이 발생했는가
- 최종 성공: 긍정적 의미와 다음 가능성으로 전환했는가
- 가장 약한 상태: 그 자리가 아무 감정적 의미도 남기지 못한 상태
- 분노·경계: 성과가 아니라 선을 넘었다는 수습 신호

## 4. 시각 방향

### 콘셉트

`Urban Field Manual × Behavioral Science Lab`

밤의 현장감을 가진 차콜 화면과 분석·연구를 보여주는 웜 아이보리 화면을 교차한다. 픽업 광고처럼 보이는 네온·과장·여성 이미지 대신, 관계 흐름과 팀 역할을 보여주는 지도·축·노드·경로를 시각 언어로 사용한다.

### 색상

- 차콜: 현장·결정·사례
- 웜 아이보리: 분석·프레임·실습 지시
- 앰버: 추진·리더·몰입
- 틸: 균형·상호성·최종 성공
- 마젠타: 긴장·경고·전환점
- 레드: 안전·멈춤·수습

### 타이포그래피

로컬 한글 폰트를 우선 사용한다. 제목은 굵고 짧게, 본문은 발표자가 읽는 원고가 아니라 청중이 한 번에 파악할 수 있는 단위로 제한한다. 화면 제목은 자연스러운 한국어 문장으로 유지하고 번역투를 피한다.

## 5. 화면 구성

각 슬라이드는 최소 하나의 시각 구조를 갖는다.

- 진행 흐름: 노드와 화살표
- 권력: 균형축
- 텐션: 감정 곡선
- 계속·안정·종료: 세 갈래 결정 트리
- 역할: 4인 관계 맵
- 명분·동선·기세: 삼각 구조
- 성공 기준: 감정 강도 × 감정 방향 매트릭스
- 사례: 타임라인과 전후 비교
- 실습: 역할 카드와 10점 관찰표

한 화면의 텍스트는 제목, 핵심 문장, 3~5개의 짧은 단위로 제한한다. 세부 설명과 진행 멘트는 발표자 노트에 넣는다.

## 6. 상호작용

### 기본 조작

- `←`, `→`: 이전·다음 슬라이드
- `Space`, `PageDown`: 다음 슬라이드
- `PageUp`: 이전 슬라이드
- `Home`, `End`: 처음·마지막 슬라이드
- 화면 좌우 클릭과 모바일 스와이프 지원
- URL 해시로 현재 슬라이드 유지 및 직접 링크

### 발표 보조

- 하단 진행률과 현재 장 번호
- `N`: 발표자 노트 열기·닫기
- `O`: 전체 슬라이드 오버뷰
- `F`: 전체화면
- `?`: 단축키 도움말
- `Esc`: 열린 패널 닫기

발표 중 방해되지 않도록 조작 UI는 기본적으로 최소화하고 마우스 움직임이나 키 입력 때만 선명하게 보이게 한다.

## 7. 기술 구조

사용자 산출물은 `outputs/5points_macro_strategy_lecture.html` 한 파일이다.

단일 파일 내부를 다음처럼 분리한다.

- `<style>`: 색상 토큰, 레이아웃, 컴포넌트, 애니메이션, 인쇄 스타일
- `<main id="deck">`: 30개 `<section class="slide">`
- `<aside id="notes">`: 현재 슬라이드의 발표자 노트
- `<dialog>` 또는 레이어: 오버뷰와 도움말
- `<script>`: 이동, 해시, 전체화면, 노트, 오버뷰, 터치 처리

외부 CDN, 웹폰트, 이미지 URL을 사용하지 않는다. 도형과 배경은 CSS와 인라인 SVG로 만든다. 파일을 복사해 다른 컴퓨터에서 열어도 동일하게 동작해야 한다.

## 8. 반응형·인쇄

- 데스크톱 발표에서는 화면을 16:9 캔버스에 맞춰 축소·확대한다.
- 모바일에서는 같은 슬라이드를 화면에 맞추고 스와이프로 이동한다.
- 인쇄 모드에서는 애니메이션과 UI를 제거하고 각 슬라이드를 한 페이지로 출력한다.
- PDF 저장 시 30페이지가 생성되도록 강제 페이지 나눔을 적용한다.

## 9. 접근성과 안전

- 키보드만으로 모든 발표 기능을 사용할 수 있어야 한다.
- `prefers-reduced-motion`에서는 전환 애니메이션을 끈다.
- 본문 대비는 프로젝터 환경에서도 읽히는 수준으로 유지한다.
- 분노·불편·취기를 성적 관심으로 해석하지 않는다.
- 동의와 선택권을 협상력의 일부로 표현한다.
- 롤플레이에는 중단·건너뛰기·디브리핑 규칙을 포함한다.

## 10. 검증 기준

- Chrome과 Edge에서 로컬 파일로 정상 실행
- 30장 모두 키보드와 클릭으로 이동
- 해시 직접 링크와 새로고침 상태 유지
- 노트·오버뷰·도움말·전체화면 작동
- 1366×768, 1920×1080에서 제목·본문 잘림 없음
- 모바일 폭에서 조작 가능
- 인쇄 미리보기에서 슬라이드별 한 페이지
- 외부 네트워크 요청 없음
- 기존 5 Points, 사례, 실습, 연구 부록, 발표자 노트 누락 없음
