# 강의 덱 템플릿

검정 바탕 + 금색 강조 + 붓글씨 헤드라인. 슬라이드를 그리지 않고 **명세를 쓰면 나온다.**

폰트·이미지가 파일 안에 박히므로 완성본 `deck.html` 하나만 있으면 **인터넷 없이도** 그대로 돌아간다.

---

## 쓰는 법

`deck.mjs` **한 파일만 고친다.** 나머지는 건드릴 일이 거의 없다.

```bash
node gen.mjs          # 명세 → 아트보드 (.dc.html)
node subset-fonts.mjs # 쓴 글자만 남겨 폰트 굽기
node build.mjs        # → deck.html (발표용 단일 파일)
node build-notes.mjs  # → notes.html (발표자 노트만, 인쇄용)
```

위에서부터 순서대로 돌린다. **글자를 고쳤으면 다시 다 돌린다** (폰트를 안 구우면 새 글자가 깨진다).
`build-notes.mjs` 는 `notes.mjs` 를 안 쓸 거면 건너뛰어도 된다.

발표 중 단축키: `←` `→` 이동 · `N` 발표자 노트 · `O` 전체 보기 · `F` 전체 화면

---

## 파일

| 파일 | 하는 일 | 고치나? |
|---|---|---|
| `deck.mjs` | **내용.** 슬라이드 명세 배열 | ✅ 여기만 |
| `notes.mjs` | 발표자 노트 (번호 → 지시문) | ✅ |
| `images/` | 배경 사진 | ✅ 넣기만 |
| `system.mjs` | 색·타이포·템플릿 19종 | ❌ 디자인 바꿀 때만 |
| `gen.mjs` `build.mjs` `subset-fonts.mjs` `build-notes.mjs` | 빌드 | ❌ |
| `fonts/*.ttf` | 원본 폰트 | ❌ |
| `examples/5points.deck.mjs` | 65장 실제 사용 예 | 참고용 |

막히면 `examples/5points.deck.mjs`를 연다. 19종을 실제로 어떻게 썼는지 다 들어 있다.

---

## 슬라이드 19종

모든 장에 공통으로 쓰는 것: `top`(우상단 작은 글자) · `tag`(좌하단) · `h`(제목) · `hSize`(제목 크기, 안 쓰면 자동) · `concl`(하단 결론 한 줄)

**글자 위주**
| type | 언제 |
|---|---|
| `img` | 배경 사진 위에 제목. 표지·파트 표지 |
| `chapter` | 큰 글씨만. 사진 없는 파트 표지 |
| `theory` | 제목 + 항목 3~4개 (+ `callout` 각주) |
| `columns` | 3~4단 나란히 비교 |
| `versus` | 좌우 둘 대비 (`left` / `right`) |
| `script` | 실제 대사. 본문만 세리프라 다른 장과 구분된다 |
| `rail` | 표처럼 행이 쌓이는 목록 (채점표 등) |
| `workshop` | 큰 숫자 + 실습 안내 |

**도식 — 모양이 곧 논리다**
| type | 모양 | 언제 |
|---|---|---|
| `flow` | 좌→우 점선 | 단계가 이어질 때 |
| `roadmap` | 정거장 5개 | 전체 지도 |
| `stairs` | 올라가는 계단 | 낮은 데서 높은 데로 |
| `gauge` | 눈금 막대 | 낮음–목표–높음 |
| `branch` | 하나 → 셋 갈림길 | 선택지가 갈릴 때 |
| `fan` | 하나 → 여럿 부채꼴 | 하나에서 파생될 때 |
| `hub` | 가운데 + 사방 넷 | 하나를 여러 각도로 |
| `axes` | 삼각형 세 꼭짓점 | 세 축이 균형 |
| `loop` | 돌아오는 순환 | 올렸다 되돌릴 때 |
| `formula` | A × B × C = | 곱셈 (하나가 0이면 전체 0) |
| `diagram` | 전열 도식 | 팀 배치 전용 |

**같은 모양을 연달아 쓰지 않는다.** 세 장 연속 `theory`면 강의가 지루해진다.

## 명세 예시

```js
// 목록형
{ type:'theory', top:'1부 · 一', tag:'1부 01',
  h:'주장을 한 문장으로', sub:'왜 그런지 한 줄',
  items:[ {t:'첫째', d:'설명.'}, {t:'둘째', d:'설명.'} ],
  callout:'오른쪽에 박히는<br>한 마디' }

// 단계형 — red:true 면 그 마디가 빨강
{ type:'flow', h:'이렇게 흘러간다',
  steps:[ {k:'A · 시작', t:'첫 단계', d:'설명.'},
          {k:'B · 문제', t:'두 번째', d:'설명.', red:true} ],
  concl:'결론 한 줄' }

// 배경 사진 — align 으로 글자 위치를 정한다
{ type:'img', img:'cover.jpg', align:'right', pos:'42% 45%',
  kicker:'CASE', h:'제목', hSize:150, sub:'부제' }
```

---

## 알아둘 것

- **제목이 두 줄로 깨지면** `hSize`를 줄이거나 `w`(글상자 폭)를 늘린다. 붓글씨는 글자가 거의 정사각형이라 5글자면 이미 900px을 넘는다.
- **사진 위 글자가 안 읽히면** `align`을 반대로 준다 (`left` ↔ `right`). 그늘이 그쪽으로 따라간다.
- **줄바꿈**은 `<br>`. 따옴표는 `“ ”`를 쓴다.
- **이미지는 1200px / 품질 72 정도**면 충분하다. 더 키우면 파일만 무거워진다.
- **폰트**: 헤드라인 East Sea Dokdo(붓글씨), 본문 Noto Sans KR, 대사 Noto Serif KR. 전부 Google Fonts 무료.
- 한 번에 쓰는 강조색은 **한 장에 하나**. 금색이 기본, 빨강은 "여기가 문제다" 할 때만.
